# Spec: content-quality

기능 ID `content-quality` · 위치 `packages/contracts`(가이드 스키마), `packages/database`(저장·생성·검수·렌더), `apps/console`(가이드 편집·템플릿 적용) · 테스트베드: mellow

## 목표

자동 생성 콘텐츠의 질을 올린다. 제품마다 다른 것은 **데이터(콘텐츠 가이드)**로만 표현하고, 생성·검수·디자인 동작은 모든 제품이 같은 코드를 쓴다. 특정 제품 이름·문구·색·레이아웃을 코드에 넣지 않는다. mellow 가이드는 Console 화면(또는 API)으로 입력하는 데이터이며 코드·마이그레이션에 없다.

## 콘텐츠 가이드 (제품별 데이터)

`projects.guide jsonb`. 프로필의 일부라서 저장하면 프로필 버전이 올라가고 `profile_versions` 스냅샷에 함께 남는다. 생성 견적은 프로젝트 행 전체를 스냅샷하므로 그 시점의 가이드로 생성된다.

| 필드 | 뜻 | 쓰는 곳 |
|---|---|---|
| `pillars[]` `{name, description}` ≤6 | 이 제품이 반복해서 말할 주제 기둥 | 기획 프롬프트(후보는 기둥 하나를 고르고 `pillar`로 밝힘), 이력 비교 |
| `examples[]` `{channel?, text, note}` ≤10 | 좋은 예시 글. 문장 수준·구체성의 기준 | 기획·검수 프롬프트(복제 금지, 수준만 참고) |
| `counterExamples[]` `{text, reason}` ≤10 | 피해야 할 글과 이유 | 기획·검수 프롬프트 |
| `bannedPhrases[]` ≤40 | 결과에 있으면 안 되는 정확한 문구 | 결정적 검사(대소문자·공백 무시) |
| `requireWebsite` | 캡션에 프로필 웹사이트 주소 필수 | 결정적 검사 |
| `hashtags` `{fixed[], max}` | 항상 붙일 해시태그와 최대 개수 | 결정적 검사·후처리 |
| `visual.photoStyle` | 사진 연출 지시(영문 권장) | 미디어 프롬프트에 덧붙임 |
| `visual.template` | `none` · `photo-headline` · `color-card` | 이미지 후처리 렌더 |
| `visual.palette` `{background, ink, accent}` | 템플릿 색 | 렌더 |
| `visual.tagline` | 하단 보조 문구 | 렌더 |
| `visual.logoAssetId` | 업로드한 로고(PNG/JPEG/SVG 아님) | 렌더 |

빈 가이드는 가이드 문단을 프롬프트에 넣지 않는다. 템플릿용 필드(`pillar`·`headline`·`subline`)는 항상 요청하되 비어 있어도 된다.

## 생성 파이프라인 (공통)

1. **기획**: 프로필 + 가이드 + 이력으로 후보 3개. 이미지 후보는 템플릿용 `headline`(1–2줄)과 `subline`도 낸다. 모든 제품에 같은 **후킹 규칙과 공통 형식**을 적용한다: 첫 줄로 멈추게 하기(제품명·일반적 혜택으로 시작 금지), 설명 대신 실제 사용 장면, 가볍게 재미있게, 한 글에 한 가지. 후보마다 다른 형식을 고른다 — 실사용 장면 · 공감 상황 · 전후 비교 · 오늘 해 볼 팁 · 가벼운 유머/상황극 · 댓글 질문 (`CONTENT_FORMATS`).
2. **결정적 검사**: 채널 길이, 금지 문구(가이드 + 공통: AI 제작 고지 문구), 웹사이트 필수, 해시태그 개수. 위반 후보는 탈락.
3. **중복 제거**: 기존 이력과 겹치는 후보를 비용이 드는 검수 전에 제외한다.
4. **검수(LLM)**: 남은 후보를 가이드 기준으로 채점 — 구체성·브랜드 적합·사실 근거·후킹(가중 2배)·재미. 근거 없는 사실이나 반례와 같은 글은 탈락. 점수 순으로 정렬하고, 잠금 안에서 이력을 다시 확인해 가장 높은 후보를 고른다.
5. **미디어**: 미디어 프롬프트에 `visual.photoStyle`을 덧붙여 생성.
6. **템플릿 렌더**: 이미지이고 템플릿이 있으면 사진 + 헤드라인 + 로고 + 팔레트로 1080×1350 포스터를 만들어 게시물 이미지로 쓴다. 원본 사진은 생성 작업 자산으로 남는다.

검수 단계 실패(공급자 오류)는 생성 실패로 처리하고 자동 재시도하지 않는다(기존 결제 안전 원칙).

## 템플릿 렌더러 (공통)

서버(worker·api)에서 `sharp` + `@resvg/resvg-js`로 렌더한다. 폰트는 저장소에 둔 Pretendard(OFL) 파일을 명시적으로 불러서 시스템 폰트에 의존하지 않는다. 템플릿은 코드에 있는 **레이아웃 프리셋**이고 색·문구·로고는 모두 입력값이다.

- `photo-headline`: 사진 꽉 채움, 위·아래 그라데이션, 2줄 헤드라인(둘째 줄 accent), 보조 문장, 하단 로고 + tagline.
- `color-card`: 사진 없이 배경색, 큰 헤드라인, 로고 + tagline. 글 게시물 이미지·공지용.

Console 편집 화면에서 기존 게시물에도 "템플릿으로 디자인"으로 같은 렌더러를 쓴다(헤드라인 직접 입력, `POST projects/:slug/templates/:postId`). 템플릿이 그려진 원본 사진은 `posts.sourceAssetId`에 남겨 다시 적용해도 글자가 겹치지 않는다.

## 완료 조건

- 가이드가 비어 있는 제품의 생성 결과·요청 형식이 바뀌지 않는다(테스트).
- 가이드 저장 → 프로필 버전 증가, 스냅샷에 가이드 포함(테스트).
- 결정적 검사가 금지 문구·웹사이트 누락·해시태그 초과 후보를 걸러낸다(테스트).
- 검수 점수 순 선택과 전원 탈락 시 실패(테스트, 공급자 모킹).
- 렌더러가 두 템플릿을 한글 헤드라인으로 1080×1350 PNG로 만든다(테스트 + 눈 확인).
- 코드에 제품 slug·문구 분기가 없다(검색으로 확인).
- mellow 가이드를 Console에서 입력하고, 운영에서 글 생성 1건과 기존 사진 템플릿 적용 1건으로 확인한다. 이미지 생성은 Higgsfield API 잔액이 생긴 뒤.

## 다음 기능: 다국어 채널 (`multilingual-channels`)

운영자 요청(2026-10-02). 지금은 제품·채널마다 계정 하나(`channel_connections` 기본 키 `workspace·project·channel`)이고 콘텐츠 언어는 ko·en뿐이다. 다국어로 가려면 채널 연결에 언어(또는 지역) 축을 더하고(예: mellow 인스타 한국어 계정·영어 계정), 생성 요청·가이드 예시·템플릿 하단 문구를 언어별로 고를 수 있어야 한다. 채널 연결 기본 키와 게시 큐 계약이 바뀌는 DB·API 전환이므로 이 기능과 분리해 별도 명세로 진행한다. 이번 가이드는 예시에 채널을 붙일 수 있고, 템플릿 헤드라인은 게시물 언어로 생성되어 언어가 늘어도 그대로 쓴다.
