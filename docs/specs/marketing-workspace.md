# Spec: marketing-workspace

기능 ID `marketing-workspace` · 위치 `apps/console`, `apps/api`, `packages/database`, `packages/contracts`

## 목표

마케팅을 잘 모르는 운영자도 Console 첫 화면만 보고 "이번 주에 무엇을 결정하면 되는지" 알 수 있게 한다. 화면 구조는 `docs/marketing/16-marketing-methodology-2026.md`의 원칙을 따른다: 메시지를 먼저 시험하고 이긴 것만 키운다, 채널은 셋을 시험해 하나를 남긴다, 주 3~5회 꾸준히, 볼 숫자는 셋, 단계마다 예산 상한, 시즌·피처링 마감을 미리 챙긴다.

운영자의 일은 결정(승인, 돈, 제품 사실 확인)과 Claude가 못 하는 일(녹화, 로그인, 결제)뿐이다. 기획·제작·예약·기록은 Claude가 맡는다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | **이번 주** 첫 화면 + **예약 게시** | 완료 (2026-10-07) |
| 2 | **메시지 실험**: 콘텐츠의 메시지 꼬리표, 메시지별 반응 비교(저장+공유 ÷ 도달), 30일 판정 | 완료 (2026-10-07) |
| 3 | **직접 해 주셔야 해요** 목록, **캘린더**(시즌·피처링 마감), **예산**(월 사용액과 상한) | 예정 |
| 4 | **채널 보드**(시험 중·유지·중단), 제품 화면 정리 | 예정 |

## 1단계: 이번 주 + 예약 게시

### 예약 게시

- 승인된 콘텐츠에 게시 시각을 정할 수 있다. 그 시각이 되면 worker가 운영자가 직접 누른 것과 같은 검사(최신 제품 정보 확인, 채널·언어 계정, 게시 형식, 중복 방지)를 거쳐 게시를 시작한다.
- 저장: `posts."scheduledAt"`, `"scheduledBy"`, `"scheduledConnectionRevision"`, `"scheduledRevision"`. 예약은 게시물 버전(`revision`)에 묶인다. 수정, 되돌리기, 제품 정보 변경으로 버전이 바뀌면 예약은 자동으로 무효가 되고 화면에서도 사라진다.
- 예약한 사람과 그때 확인한 계정 버전으로 게시한다. 그사이 계정 연결이 바뀌었으면 게시하지 않고 실패로 기록한다("게시할 계정이 바뀌어 예약 게시를 하지 않았어요").
- 과거 시각은 5분까지만 허용하고, 60일보다 먼 시각은 막는다.
- API: `POST projects/:slug/posts/:id/schedule {revision, scheduledAt, connectionRevision}`, `POST projects/:slug/posts/:id/unschedule {revision}`.

### 이번 주 화면 (첫 화면)

1. **승인이 필요해요**: 모든 제품의 초안. 카드마다 제품, 채널·언어, 형식, 제목. "승인하고 예약"(추천 시각이 미리 채워짐)과 "열어 보기".
2. **이번 주 일정**: 예약된 콘텐츠를 시각순으로. "예약 취소".
3. **이번 주 게시됨**: 이번 주 게시된 콘텐츠와 링크.
4. 그 아래에 기존 제품 목록과 최근 작업.

추천 시각: 같은 제품·채널의 기존 예약을 피해 다음 월·수·금 오후 7시(KST).

## 완료 조건 (1단계)

- 예약 → 시각 도래 → 게시 큐 진입, 운영자 직접 게시와 같은 검사(테스트).
- 예약 뒤 수정·되돌리기·제품 정보 변경 시 게시되지 않음(테스트).
- 계정 연결이 바뀌면 실패로 기록하고 게시하지 않음(테스트).
- 첫 화면에서 승인+예약, 예약 취소가 동작(로컬 화면 확인).
- 기존 지금 게시, 게시 기록, 콘텐츠 편집 동작이 바뀌지 않음(기존 테스트).

## 2단계: 메시지 실험

- `content_messages`(제품별, 최대 12개, 상태 시험 중·이긴 메시지·그만둠), `posts."messageId"`, `post_metrics`(게시물당 한 줄: 도달·저장·공유·좋아요·댓글·프로필 방문·링크 클릭).
- 메시지 꼬리표는 기획 정보라 게시물 버전과 승인을 바꾸지 않는다. 결과는 게시된 콘텐츠만 기록하고, 다시 기록하면 덮어쓴다. 저장+공유가 도달의 5배를 넘으면 입력 실수로 보고 막는다.
- 비교 지표는 조사 보고서대로 (저장+공유) ÷ 도달. 판정: 시험 중인 메시지가 둘 이상이고 각각 측정된 게시물이 3개 이상일 때, 1위가 2위의 1.5배 이상이면 "이긴 메시지로 정해도 돼요". 그 전에는 앞선 메시지만 알려 준다. 이긴 메시지 지정은 운영자가 누른다.
- 화면: 제품 화면 맨 위 "메시지 실험"(메시지별 콘텐츠·게시·측정 수, 도달, 저장+공유, 반응률 막대, 판정 문구, 메시지 추가·이긴 메시지로·그만두기·다시 시험). 편집 화면 "메시지 실험"(메시지 선택, 게시 뒤 결과 입력과 반응률).
- API: `GET/POST projects/:slug/messages`, `PATCH projects/:slug/messages/:id`, `POST projects/:slug/posts/:id/message`, `POST projects/:slug/posts/:id/metrics`.
- 결과 숫자는 지금 운영자나 Claude가 인사이트에서 옮겨 적는다. Instagram·Buffer 인사이트 자동 수집은 이후 단계로 남긴다.
