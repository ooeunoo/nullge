# 구현 순서와 완료 조건

작성: 2026-09-25 · 전체 로드맵. M1과 M2 일부를 구현했으며 실제 완료 범위는 08 문서에 기록한다.

| ID | 작업 | 필요한 검증 |

| N-04 | 게시물·캠페인·미디어·편집 화면 | 동시 편집 충돌, 제품 전환, 잘못된 미디어/외부 제품 ID 거절 |

N-01 → N-02 → N-03/N-04 → N-05/N-06 → N-07/N-08 → N-09/N-10 순서로 의존한다. N-09 화면은 초기 프로토타입에서 먼저 검토하고 실제 데이터 연결을 뒤에 마친다.

## 핵심 회귀 시나리오

1. mellow 편집 화면에서 ClipIt의 게시물·미디어·계정 ID로 읽기/수정/예약/다운로드하면 거절된다.
2. AI가 mellow 작업을 할 때 ClipIt 최근 제목이나 제품 프로필을 받지 않는다. 반대 방향도 검증한다.
3. AI 생성 중 사용자가 본문을 편집하면 생성 결과가 최신 본문을 덮지 않는다.
4. 승인 후 본문·링크·미디어·계정 변경 또는 프로필 갱신이 있으면 이전 승인이 발행에 쓰이지 않는다.
5. 제품을 바꾸거나 다른 탭을 열어도 OAuth 콜백이 시작한 제품에만 연결된다. state 재사용은 거절된다.
6. 토큰 자동 갱신의 동시 실행을 제어하며 재연결·계정 교체와 구분한다.
7. 큐 중복 전달·두 Worker 실행·재시작에도 승인된 발행을 중복 요청하지 않는다.
8. 공급자가 수락한 뒤 응답이 사라지면 결과 확인 필요로 남는다. 타임아웃을 단순 실패로 재발행하지 않는다.
9. 전체 중지·제품 중지·계정 연결 해제·예약 취소가 실행 직전 일어나면 최종 검사를 통과하지 못한다. 이미 보낸 요청은 결과 확인으로 처리한다.
10. 한 제품의 긴 영상 작업·연결 실패·한도 소진이 다른 제품의 정상 작업을 막지 않는다.
11. import를 반복해도 콘텐츠·미디어·이벤트가 늘지 않고 참조와 외부 결과가 유지된다.
12. 되돌리기 연습에서 새 시스템이 발행한 콘텐츠를 이전 Worker가 다시 게시하지 않는다.

이 시나리오는 도메인/DB/공급자 모의 응답으로 반복 검증한다. 이후 실제 화면과 계정에서 별도 검증한다. 테스트 성공과 실제 공개 발행 성공을 동일하게 보고하지 않는다.

## 외부 연결 검증 기록 양식

각 채널 검증에는 날짜·제품·채널·계정 식별자·지원 형식·내부 Post/Publication ID·외부 ID/링크·결과를 남긴다. 토큰이나 OAuth 코드는 포함하지 않는다.

문구와 미디어가 검토된 후 사용자가 요청한 범위에서 실제 발행한다. 계정이 준비되지 않으면 필요한 조치와 마지막 확인일을 기록하고 독립적인 구현 작업을 계속한다. 테스트 대체 응답을 실연동 증거로 채우지 않는다.

파일럿 완료 조건:

- 두 제품 각각의 실제 계정으로 1건 이상 발행하고 외부 결과를 확인했다.
- 각 제품의 초안·미디어·이력·한도가 분리되고 예약 취소/수정이 실제 화면에서 동작한다.
- 이전 mellow 실행기와 새 실행기가 동시에 마케팅을 실행하지 않는다.
- 실패·결과 불명·토큰 만료 상황의 운영 절차를 실제로 따라갈 수 있다.
- 지원 채널별로 구현/연결/실발행 검증 범위가 기록되어 있다.
- 7일 운영에서 발견된 문제와 남은 외부 의존성을 기록했다.
