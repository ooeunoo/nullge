# mellow에서 옮기는 방법

작성: 2026-09-25 · 계획만 작성. 원본 코드·DB·토큰·배포 설정은 변경하지 않았다.

## 출발점과 마지막 운영 기록

현재 소스에서 콘텐츠 편집, AI 기획·문구 검사, 미디어 업로드, 계정 연결, 예약·발행 상태와 중복 방지 로직을 확인했다. 운영 상태는 실시간 조회가 아니라 다음 기록에 근거한다.

`mellow/docs/marketing/resume-2026-09-14.md`의 마지막 기록:

- 초안 총 8개: 기존 Instagram·Threads 6개와 X 2개.
- X 전용 계정 `@mellow_call` 연결 완료. 계정 연결과 요청 권한 확인이 기록되어 있다.
- AI 문구 기획·보조 검사 실제 실행 이력이 있다.
- Higgsfield API 키는 저장되어 있었고, 당시 대시보드의 가용 크레딧은 0이었다.
- Instagram·Threads 미연결, 자동 운영·발행 허용 꺼짐, 실제 발행 미검증.

9월 12~13일의 'X 계정 선택 대기·초안 6개'는 이 기록으로 갱신된다. 이관 직전에는 현재 DB와 계정 상태를 다시 읽고 차이를 기록한다. 위 개수·잔액·연결 상태를 현재값으로 고정하지 않는다.

## 이관 단계

### 1. 독립 기능 검증

새 DB와 가상 계정 응답으로 mellow·ClipIt 프로필, 초안·미디어·이력 경계를 검증한다. 운영 토큰을 개발용 테스트에 넣지 않는다. 기존 mellow 기능은 계속 보존한다.

### 2. 읽기 전용 조사와 사전 점검

현재 콘텐츠·미디어·이벤트·설정의 수량, 상태, 참조 관계, 처리 중 작업을 확인한다. 값 대신 식별자·건수·checksum을 기록한다. 원본 DB 백업과 복구 절차가 마련되어 있어야 한다.

내보내기는 기본적으로 dry-run이며 실제 데이터 파일은 비공개 임시 경로에 보관한다. 저장소에는 토큰·미디어 원본·운영 DB 덤프를 커밋하지 않는다.

### 3. 비활성 상태로 가져오기

새 서비스에 Nullge/mellow 프로젝트를 만들고 기존 콘텐츠를 매핑한다. `sourceSystem + sourceId`에 유일 키를 두어 같은 이관을 반복해도 데이터가 중복되지 않게 한다.

- 원본 제목·본문·언어가 알려진 경우 언어·채널·시간·외부 게시물 ID·링크·오류 정보를 보존한다.
- 미디어를 새 저장소로 복사하고 바이트 크기와 checksum, 게시물 참조를 대조한다.
- 기존 이벤트의 사용자 식별자는 외부 출처 정보로 보존한다. 새 운영자 ID로 임의 치환하지 않는다.
- 초안은 초안으로 가져온다. 기존 예약은 원래 예정 시각을 보존하되 비활성·재검토 상태로 가져온다.
- 처리 중·결과 불명 작업은 정리 전 재실행하지 않는다. 이미 공개된 콘텐츠는 발행 이력으로만 가져온다.
- 공급자 키와 계정 토큰은 콘텐츠 import에 포함하지 않는다. 모든 발행 허용과 자동 운영은 꺼짐으로 시작한다.

행 수·상태별 수량·미디어 해시·채널·본문·시간·외부 ID를 검증 보고서로 대조한다. 대표 초안과 미디어를 실제 화면에서도 확인한다.

### 4. 채널 재연결

기본안은 새 Console에서 계정을 다시 연결하는 것이다. 특히 X 앱 콜백은 새 주소를 등록하고 재인증하되, 검증 전 기존 콜백을 제거하지 않는다. 새 연결은 정확한 제품과 외부 계정 ID를 대조한다.

예외적으로 기존 자격 증명 이동이 필요하면 전용 비공개 일회성 도구를 설계한다. 기존 값은 AES-256-GCM과 `mellow-marketing-v1` AAD를 쓰므로 이름만 바꾸면 복호화할 수 없다. 원래 키와 AAD로 메모리에서 복호화한 뒤 새 키·포맷으로 재암호화하고, 평문 파일이나 로그를 남기지 않는다. 암호화 키를 새 서비스 설정에 무작정 공유하지 않는다.

토큰·앱 설정·호스팅 도메인을 옮겼다는 이유만으로 공급자 권한·잔액·실제 생성/발행이 검증되었다고 보지 않는다.

### 5. 단일 실행 주체로 전환

원본 마케팅 편집·예약을 잠시 중지하고 진행 중 외부 요청의 결과를 먼저 확인한다. 동결 시점 이후 차이를 최종 가져오고 검증한다. 사용자에게 보이는 원본 화면도 읽기 전용/이동 안내로 전환한다.

기존 mellow Worker의 마케팅 작업 등록·처리를 비활성화한 것을 확인한 뒤 새 Worker만 활성화한다. 두 실행기를 동시에 켜지 않는다. 제품의 통화 등 다른 Worker 기능은 그대로 유지한다.

새 서비스에서 최종 검토한 실제 게시물을 대상으로 발행하고, 외부 게시물과 내부 ID·링크를 비교한다. 유료 사용·공개 게시·운영 전환은 그 시점의 사용자 지시 범위에 따라 수행한다. 이 기획 작성 자체가 그 실행 지시는 아니다.

### 6. 관찰과 정리

7일 운영과 회귀 검증 후 mellow 어드민의 메뉴를 Nullge Console 링크로 바꾼다. 과거 데이터·암호화 키·API 제거는 별도 보존/복구 기간을 정한 뒤 진행하며 첫 전환에서 삭제하지 않는다.

## 되돌리기

새 Worker와 예약을 먼저 멈추고 진행 중 외부 요청 결과를 대조한다. 새 서비스에서 생성/수정/발행한 콘텐츠를 별도로 정리한 뒤 실행 주체를 하나만 선택한다. 원본 Worker를 즉시 다시 켜서 기존 예약을 재실행하지 않는다.

공개 게시물과 공급자 비용은 DB를 되돌린다고 취소되지 않는다. 새 시스템에서 발행한 외부 ID를 보존하고 원본의 같은 콘텐츠를 재예약하지 않는다. 외부 결과가 확정되지 않으면 그 항목은 수동 확인 상태로 남긴다.
