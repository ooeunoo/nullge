# 제품 기획

작성: 2026-09-25 · 기본안

## 해결할 문제

제품이 늘어날수록 홍보 문구·브랜드 자료·SNS 연결·게시 일정이 여러 어드민으로 흩어진다. 운영자는 매번 제품 설명을 다시 전달해야 하고, 어느 제품에 어떤 콘텐츠가 필요한지 확인하기 어렵다. 같은 예약·발행 코드를 제품별로 유지하는 비용도 늘어난다.

Nullge에서 제품별 맥락을 보관하고 공통 제작·발행 기능을 제공한다. 제품을 추가할 때는 프로필과 계정을 등록하며, 기본적인 홍보를 위해 해당 제품의 서버를 수정할 필요가 없어야 한다.

## 사용자와 핵심 사용 상황

첫 사용자는 여러 제품을 만드는 Nullge 운영자 1명이다. 외부 고객 가입·요금제·대행사·팀 승인 체계는 첫 버전에 포함하지 않는다.

| 상황 | 운영자가 하려는 일 | 필요한 결과 |
| --- | --- | --- |
| 아침 확인 | 오늘 올라갈 글과 검토할 작업을 본다 | 전체 제품의 일정·주의할 작업이 한 화면에 보임 |
| 새 제품 추가 | 제품 설명·대상·브랜드·채널을 등록한다 | 기존 제품과 섞이지 않는 작업 공간 |
| 콘텐츠 제작 | 목표와 소재를 주고 채널에 맞게 글을 만든다 | 제품 사실과 말투를 반영한 편집 가능한 초안 |
| 발행 준비 | 문구·이미지·계정·시각을 확인한다 | 확인한 버전 그대로 예약됨 |
| 문제 대응 | 토큰 만료나 발행 실패 원인을 확인한다 | 필요한 조치와 외부 발행 여부를 구분할 수 있음 |

## 제품의 중심 개념

- **작업공간:** Nullge. 초기에는 하나만 만들고 운영자만 접근한다.
- **제품:** mellow, ClipIt, minimo, desk. 사용자 화면에서는 제품, 내부 모델에서는 Project로 부른다.
- **제품 프로필:** 제품 사실·고객층·목표·언어·브랜드·금지 표현·소개 링크. 검토한 버전으로 저장한다.
- **캠페인:** 같은 목표의 콘텐츠 묶음. 첫 버전에서는 이름·목표·기간을 갖는 선택적 분류다.
- **게시물:** 한 제품의 한 채널·한 계정에 올릴 문구와 미디어. 채널별 변형은 별도 게시물로 저장한다.
- **미디어:** 직접 올린 이미지·영상 또는 생성 결과. 제품별로 소유하고 원본과 사용 이력을 남긴다.

여러 채널용 문구를 만들 수 있어도 첫 버전의 검토·예약·결과 확인은 게시물별로 한다. 한 채널의 실패가 다른 채널 게시물을 다시 발행하게 해서는 안 된다.

## 첫 버전 범위

| 기능 | 첫 버전에서 제공할 범위 | 완료 증거 |
| --- | --- | --- |
| 독립 로그인 | 운영자만 로그인, 공개 가입 없음 | 제품 서비스의 로그인 없이 접근 가능 |
| 제품 관리 | 생성·편집·보관, 프로필 버전과 근거 기록 | 최소 4개 제품을 등록하고 두 제품으로 실제 사용 |
| 전체 보기 | 검토 대기·예약·실패·연결 조치·사용량 | 전체/제품 필터와 각 작업 연결 |
| 콘텐츠 편집 | 제목·목표·본문·언어·채널·미디어·캠페인 | 저장·재편집·충돌 감지·미리보기 |
| AI 문구 | 제품 프로필 기반 기획·변형·사실성 보조 검사 | 사용한 프로필·프롬프트·모델과 사용량 기록 |
| 미디어 | JPEG/PNG/MP4 업로드, 보관·미리보기·내려받기 | 제품별 접근과 실제 채널별 형식 검사 |
| 채널 연결 | X·Threads·Instagram 어댑터와 계정 상태 | 계정 조회·권한 점검·실발행 검증을 구분 |
| 검토·예약 | 사용자 검토, 개별 즉시 발행/예약, 일정 목록·주간 보기 | 승인한 콘텐츠·계정·시각이 발행 결과와 일치 |
| 발행 결과 | 외부 ID·링크, 실패와 결과 확인 필요 상태 | 새로고침·Worker 재시작 후에도 결과 유지 |
| 직접 게시 | 문구 복사·파일 다운로드·외부 링크 수동 기록 | API 발행과 수동 기록을 구분 |
| 운영 한도 | 프로젝트별 생성 건수, 동시 실행, 사용량·비용 추정 | 한 제품의 한도가 다른 제품 작업을 소진하지 않음 |

채널 도입 순서는 X 텍스트 → Threads 텍스트 → 이미지 → Instagram 릴스다. 이는 구현 순서이며 플랫폼의 전체 기능을 지원한다는 뜻이 아니다. 기존 X는 텍스트·단일 이미지, Threads는 텍스트·단일 이미지, Instagram은 단일 이미지·릴스가 재사용 대상이다. 새 API 계약은 구현 시 다시 확인한다.

첫 파일럿은 준비된 채널로 시작할 수 있다. 연결되지 않은 채널은 명시적으로 대기 상태로 표시한다. 두 제품에서 각각 최소 한 채널의 실제 발행이 검증되어야 파일럿 완료로 본다. 채널별 지원 완료는 그 채널의 별도 실연동 증거가 있어야 한다.

## 후속 단계

- Higgsfield 이미지·영상 생성: 기존 어댑터를 이식하되 문구·업로드·발행 흐름 검증 뒤 연결한다.
- 자동 기획: 제품·캠페인별 주기와 한도를 두고 검토 대기까지만 자동화한다.
- 무인 발행: 반복 운영에서 결과를 확인한 뒤 별도 기능으로 도입한다.
- 성과 수집: 게시물 조회·반응 지표, UTM을 통한 제품 유입 측정. 현재 사용량/발행 이력과 구분한다.
- 제품 API·릴리스 소식·ClipIt 결과물 연동: 수동 등록으로 먼저 쓰고 반복 작업이 확인되면 추가한다.

첫 버전 제외: 유료 광고 집행, 댓글·DM 자동 응답, 외부 고객 결제, 콘텐츠 도용 수집, SEO·이메일 캠페인, 모든 SNS 동시 지원, 제품별 고객 DB 통합.

## AI가 사용할 제품 정보

기획 프롬프트는 공통 작성 규칙 + 해당 제품의 검토된 프로필 + 채널 규칙 + 작업 목표로 구성한다. 사실성 검사는 같은 제품 프로필 버전을 기준으로 수행한다.

제품 기능·가격·출시 상태는 각각 근거와 확인일을 가진다. 코드나 과거 기획에서 찾았다는 이유만으로 현재 판매·출시 상태가 확인되었다고 처리하지 않는다. 확인되지 않은 사실은 문구에 사용하지 않거나 검토 대상으로 남긴다.

한 작업에는 선택한 제품의 정보와 최근 콘텐츠만 넣는다. 제품별 고객 대화·개인 프로필·결제 내역은 초기 입력에 포함하지 않는다. 로고·앱 화면은 등록한 실제 자료를 사용한다. AI 이미지의 표시 문구도 미디어 유형과 제품 정책에 맞춰 정하며 mellow의 인물 연출 문구를 모든 제품에 붙이지 않는다.

AI 검사 통과는 사용자 승인과 별개다. 편집한 본문·미디어·링크·대상 계정은 다시 검토하고 예약해야 한다. 과거 프로필로 만든 글은 차이를 표시하고 사용자가 다시 검토하게 한다.

## 성공 기준

다음 숫자는 측정된 성과가 아니라 파일럿의 제안 목표다.

- mellow·ClipIt에서 각각 3개 이상 초안을 만들어 제품 정보·말투·미디어가 섞이지 않는지 검토한다.
- 두 제품 각각 1건 이상, 실제 해당 제품 계정에 발행하고 외부 게시물과 내부 기록을 대조한다.
- 7일 동안 검토·예약·실패 대응을 이 도구에서 수행하고 반복 불편을 기록한다.
- 콘텐츠 준비 시간은 첫 5건을 기준선으로 측정해 이후 비교한다. 초기부터 시간 절감률을 주장하지 않는다.
- 데이터가 없는 지표는 0 대신 미수집/미연결로 보인다. AI 비용 추정치와 공급자 청구액을 구분한다.
