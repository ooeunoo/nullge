# Nullge 공통 마케팅 운영 기획

작성: 2026-09-25 · 상태: 기반 구현·Railway 배포, Console 도메인·운영 로그인 완료 · 작업명: Nullge Console

Nullge가 만드는 여러 제품의 홍보 콘텐츠를 한곳에서 기획하고, 검토하고, 각 제품의 SNS 계정에 발행하는 것을 목표로 한다. 현재 ClipIt·minimo·mellow·Movy·desk의 기본 프로필과 로고를 구성했다. 실제 SNS 발행은 아직 구현하지 않았다.

## 이번에 합의한 방향

- Nullge는 여러 제품을 운영하는 개인 사업자의 상위 브랜드다.
- 기존 `~/projects/eun/nullge` 저장소에서 진행한다. 별도 `marketing-studio` 저장소는 만들지 않는다.
- 기획 후 사용자 승인에 따라 기반 구현과 Railway 배포까지 진행했다. 기존 마케팅 데이터 이관·유료 생성·SNS 발행은 수행하지 않았다.
- 공개 회사 사이트와 Console/API/Worker, 전용 Postgres를 Nullge Railway 프로젝트에서 운영한다. DNS 전환 전에는 기존 GitHub Pages를 유지한다.
- 제품별 사용자·결제·서비스 운영은 각 제품에 남기고, 마케팅을 공통 기능으로 분리한다.

## 기획 기본안

초기에는 운영자 1명이 사용하는 내부 도구로 만든다. `Nullge Console`은 작업명이며 서비스명·도메인은 미정이다. 첫 메뉴는 마케팅이고, 다른 공통 운영 기능은 필요성이 확인될 때 별도로 기획한다.

| 구분 | 제안 |
| --- | --- |
| 저장소 | 기존 `nullge` 안에 운영 웹·API·Worker를 추가 |
| 회사 소개 사이트 | 현재 정적 파일은 유지하고 호스팅을 Railway로 이전. DNS 전환 대기 |
| 내부 운영 앱 | 독립 로그인과 별도 실행 환경. 주소 후보는 `console.nullge.com` |
| 사용 흐름 | 전체 작업 확인 → 제품 선택 → 콘텐츠 제작·검토·예약 → 결과 확인 |
| 초기 운영 | 사람이 검토하고 예약. 자동 기획·무인 발행은 후속 단계 |
| 첫 검증 | 서로 다른 두 제품의 콘텐츠를 각 제품 계정에 실제 발행 |

## 현재 저장소와 문서의 관계

현재 저장소에는 기존 회사 소개 페이지와 실행 가능한 Console/API/Worker·전용 DB 스키마가 있다. 공개 사이트의 Railway 이미지에는 허용된 정적 파일만 포함한다. DNS 전환 전까지 `.github/workflows/pages.yml`과 기존 사이트는 보존한다. 저장소는 공개되어 있으므로 비밀 값·토큰·운영 데이터는 커밋하지 않는다.

문서에서 `합의`는 사용자가 정한 방향, `기본안`은 구현을 위해 제안하는 선택, `미정`은 후속 결정이 필요한 항목이다. 계획에 적힌 기능을 이미 구현되었거나 운영에서 검증된 것으로 읽지 않는다.

현재 동작하는 범위는 제품 선택·브랜드 프로필 버전·초안 저장·검토와 복사다. `https://console.nullge.com`의 HTTPS 및 운영자 Google 로그인 연결을 완료했다. 예약·AI·SNS 연결·미디어·신규 제품 등록 UI는 아직 없다. 공개 사이트 도메인 이전/백업 연결을 마친 뒤 후속 기능을 순차적으로 구현한다.
